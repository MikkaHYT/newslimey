# Deployment

NOTE: This file was generated by AI (GitHub Copilot) on 2025-11-14.

Guidelines for deploying TPNEBOT to production like environments.

## Baseline Assumptions
- Target platform: Linux host or container (Windows acceptable for development).
- Postgres accessible locally or over secure network channel.
- Python 3.11+ installed.

## Steps (Bare Metal)
1. Create dedicated system user:
   useradd -r -s /bin/false tpnebot
2. Install Python and Postgres packages via system package manager.
3. Clone repository into a directory owned by tpnebot user.
4. Create virtual environment and install requirements:
   python -m venv /opt/tpnebot/venv
   source /opt/tpnebot/venv/bin/activate
   pip install -r requirements.txt
5. Create `.env` with production credentials (restrict file permissions).
6. Test run:
   python bot.py
7. Configure systemd unit (example skeleton):
```
[Unit]
Description=TPNEBOT Discord Bot
After=network.target

[Service]
Type=simple
User=tpnebot
WorkingDirectory=/opt/tpnebot
EnvironmentFile=/opt/tpnebot/.env
ExecStart=/opt/tpnebot/venv/bin/python bot.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```
8. Enable service:
   systemctl enable tpnebot
   systemctl start tpnebot

## Docker (Suggested)
### Dockerfile (Example Sketch)
```
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt ./
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["python", "bot.py"]
```
Build and run:
```
Docker build -t tpnebot:latest .
Docker run --env-file .env --name tpnebot --restart unless-stopped tpnebot:latest
```
Note: Ensure Postgres hostname inside URL references service name or external host.

## Optional: Local Vocal Separation (Karaoke)
- Karaoke plays a real instrumental when one can be made. `utils/core/separate.py` runs Demucs in a background subprocess and caches the result beside the song as `<name>.karaoke.ai.m4a`; with no separator installed, karaoke uses the DSP chain in `utils/core/radio.py` exactly as before.
- Install it with the project's own interpreter: `venv/bin/python scripts/install_local_separator.py` (`--check` only reports). The script refuses any other interpreter, because a venv copied from another project can carry a `pip` that installs into *that* project.
- Everything it downloads stays under `<project>/.cache` — wheels, the Rust toolchain, model weights and the scratch tree — so the host's root partition is not touched. `utils/core/separate.py` points `TORCH_HOME`, `HF_HOME` and `TMPDIR` at the same place at runtime.
- The script handles the awkward parts of ARM64: torch comes from the CPU wheel index (the default wheel pulls in CUDA packages), `sphn` has no aarch64 wheel so it is compiled with a project-local Rust, and Opus is linked through `OPUS_LIB_DIR` instead of requiring `libopus-dev` and CMake.
- Demucs runs through `utils/core/vocals.py` rather than `-m demucs`, because torchaudio on this host writes files only through TorchCodec, which does not load here; that module swaps the one call for a WAV writer from the standard library.
- Separation is CPU-bound and serialized: 20 s of audio takes about 20 s, a full 3:33 song took 479 s on a 2-core ARM host. It never blocks playback — the DSP render plays until the file lands, and the file is then reused forever.

## Environment Separation
- Use distinct tokens and seeds per environment (dev, staging, production).
- Avoid running development fairness seed rotation in production without auditing.

## Observability
- Tail `discord.log` for operational events.
- Consider exporting metrics: integrate a small HTTP server or push counters to external monitoring.

## Backups
- Database dumps (pg_dump) on regular schedule.

## Scaling
- For large guild counts: consider sharding (discord.py has sharding support).
- Use connection pool tuning for asyncpg (configure in manager code).

## Zero Downtime (Optional)
- Use rolling container updates or systemd service restart with health checks.
- Persist seeds and wallet state before upgrade.

## Security Hardening
- Restrict outbound network if not needed.
- Keep dependencies pinned but update when security patches release.
- Monitor resource usage (memory, CPU) and set ulimits where appropriate.
